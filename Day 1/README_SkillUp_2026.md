# 🚀 SkillUp 2026 --- Build, Debug & Create with AI

> **Less passive learning. More building.**\
> A hands-on workshop where you explore web development, experiment with
> AI tools, solve coding challenges, and create projects you can show
> off.

Welcome to **SkillUp 2026**! This workshop is designed for students who
want to understand how modern development works---not just copy code and
hope it runs.

You do **not** need to be an expert to participate. Bring your
curiosity, your laptop, and a willingness to experiment.

------------------------------------------------------------------------

## 🎯 What you'll do

By the end of the workshop, you'll have had the opportunity to:

-   Understand the essentials of **HTML and CSS**.
-   Explore how AI coding assistants can help you build and debug.
-   Work with a team to fix bugs in an existing website.
-   Build a frontend inspired by a popular website.
-   Create the first version of your own **portfolio website**.
-   Learn the basics of **Git and GitHub** to track and share your work.
-   Explore useful AI tools for research, productivity, design, and app
    building.
-   Understand the basic idea behind **Large Language Models (LLMs)**
    and experiment with prompts in Google Colab.
-   Get a first look at JavaScript, APIs, JSON, the DOM, and an
    interactive task manager project.

> **The goal isn't to memorise everything. It's to try things,
> understand what you're doing, and leave with something you've built.**

## 🗓️ Workshop roadmap

### Day 1 --- Web fundamentals, AI-assisted building & version control

#### 🌐 Session 1: Build a website

We'll cover just enough web development to get started, then put it into
practice.

**You'll explore** - What HTML, CSS, and JavaScript do. - Essential HTML
elements and CSS styling. - Classes, selectors, spacing, and basic
layouts. - How AI coding assistants can help with code.

**Hands-on activities** 1. Follow a short live-coding example. 2. Open a
starter project and compare its output with reference screenshots. 3.
Work in a team to identify and fix intentional bugs. 4. Choose a website
idea and build a frontend inspired by it. 5. Test your work, improve it,
and show what you made.

**Website ideas may include** - A Spotify-inspired music interface. - An
Amazon-inspired product page. - A MakeMyTrip-inspired travel page. - A
Netflix-inspired movie browser. - A Zomato-inspired restaurant page. - A
college event landing page.

These are **frontend-inspired prototypes**, not complete copies of
commercial services. You won't need real payments, accounts, or booking
systems.

#### 🧑‍💻 Session 2: Your portfolio + Git and GitHub

Turn your skills and projects into a simple personal website.

**Portfolio sections you can include** - About me - Skills - Projects -
Contact links

You'll also learn how developers keep track of code changes and share
projects.

**Git concepts** - **Git:** a version-control tool that tracks changes
in your files. - **GitHub:** an online platform for hosting repositories
and collaborating. - **Repository:** a project's files and their version
history. - **Commit:** a saved checkpoint of your changes. - **Push:**
send local commits to a remote repository. - **Pull:** bring changes
from a remote repository into your local copy. - **Clone:** create a
local copy of a remote repository. - **Branch:** a separate line of work
for making changes independently.

We'll demonstrate the workflow using the VS Code terminal and/or a
graphical Git client. You don't need to memorise every command; focus on
understanding the process.

Useful commands to recognise:

``` bash
git status
git clone <repository-url>
git add .
git commit -m "Describe your changes"
git pull
git push
```

Run commands in the correct project folder. If a command fails, read the
message and ask for help rather than repeatedly running commands you
don't understand.

## 🧠 LLMs: Behind the Chat

We'll also explore the basics of **Large Language Models (LLMs)**---the
technology behind tools such as ChatGPT, Gemini, and Claude.

### The key ideas

-   **LLM:** a model trained to learn patterns in language and generate
    responses.
-   **Tokens:** pieces of text the model processes and generates. A
    token can be a whole word, part of a word, punctuation, or another
    text unit.
-   **Parameters:** learned numerical values inside a model. Training
    adjusts these values so the model gets better at its task.
-   **Next-token prediction:** a simplified description of how many
    language models generate text---by predicting a distribution over
    possible next tokens and continuing step by step.
-   **Prompt and context:** the instructions and conversation that help
    shape the response.

More parameters do **not** automatically mean a better model. Training
data, model design, training methods, and evaluation all matter.

### Then we experiment

We'll use a prepared Google Colab notebook, where available, to compare
prompts and model outputs.

Possible experiments: 1. Ask the same question in two different ways. 2.
Give the model different audience instructions or context. 3. Improve a
vague prompt. 4. Check an answer and look for mistakes. 5. Work in a
team to produce a clear, useful explanation of a technical topic.

**Takeaway:** AI can be useful, but a confident answer is not always a
correct answer. Test, verify, and use your own judgment.

## 🏁 How the challenges work

During the workshop, you may work individually, in pairs, or in teams.

For the debugging and website challenges, you'll be encouraged to: -
Understand the task before changing code. - Compare the current result
with the expected output. - Identify and explain problems. - Use AI as
an assistant---not as a black box. - Test the result after making
changes. - Help your teammates and share what you learned.

Some challenges may include a timer, a short showcase, and small prizes.
The aim is to reward good problem-solving, creativity, teamwork, and
understanding---not just speed.

## 💡 Our approach to AI

We'll use AI to brainstorm, explain, generate, and debug---but we'll
also inspect and test its output.

A good workflow is:

**Understand → Build → Ask AI → Inspect → Test → Improve**

You are still responsible for the code and content you submit. Don't
paste secrets or personal information into AI tools, and verify
important facts before relying on them.
